## 3. CPU功能要求

### 3.1 基础功能【max：80】

1. and运算，逻辑与运算。
    
2. sll运算，逻辑左移运算，第二个操作数的低5bit是移动的位数。
    
3. sra运算，算术右移运算，第二个操作数的低5bit是移动的位数。
    
4. lui+add 运算，先做lui运算，再做add运算。(对应LoongArch 的 lu12i+add.w)
    
5. jal+auipc，具体场景后续给出 (对应 LoongArch 的 bl+pcaddu12i)
    
6. jalr+auipc，具体场景后续给出 (对应 LoongArch 的 jirl+pcaddu12i)
    
7. 实现斐波拉契数列计算，输入斐波拉契数列中数字的下标，输出对应的斐波拉契数列中的数据
    
8. 输入8bit数据，输出8bit数据中1的个数
    
9. 16bitIEEE754编码浮点数的类型判断。  
    输入16bit数据，将其作为16bit的IEEE-754单精度浮点数（符号位1bit，指数位5bit，尾数位10bit）识别，输出其对应的类型编码（0：正负0，1：正负无穷大，2：NaN，3:规约化数，4:非规约化数）
    
10. 浮点数的量化处理（16bit浮点数转为Q3.4的定点数）  
    输入16bit数据，将其作为16bit的IEEE-754单精度浮点数（符号位1bit，指数位5bit，尾数位10bit）识别，将其转为Q3.4定点数(从最高位往最低位的方向依次为：最高位是符号位，3bit的整数部分，4bit的小数部分)并进行量化，将量化的结果做输出。（测试数据包括正数和负数,如果是负数则输出对应的补码）
    

### 3.2 bonus【max：10】

1. 功能包括但不限于：复杂外设接口的支持（如VGA接口、键盘等）【max: 5】
    
    - 实现复杂度和用户体验将作为考察标准
        
2. ISA指令扩展【max：4】，如ecall（视功能复杂度评分【max：2】），浮点数指令（视功能复杂度评分【max：3】）等，或其他硬件加速指令（视功能复杂度评分【max：4】）
    
    - 直接用'*', '/'等verilog操作符实现的指令不额外加分。
        
    - 需自行提供测试用例，并说明实现该扩展指令相比于课上CPU结构所做修改，以及相比纯软件实现对性能的提升。
        
#### 已实现：RV32M 整数乘除法扩展

- 指令范围：支持 `mul`、`mulh`、`mulhsu`、`mulhu`、`div`、`divu`、`rem`、`remu` 八条 RV32M R-type 指令。
- 数据通路修改：将 `alu_ctrl_op` 从 4 bit 扩展为 5 bit，用 `10000` 至 `10111` 编码上述乘除法/取余操作；`Decoder` 通过 `funct7=0000001` 与 `funct3` 识别 RV32M 指令。
- 硬件实现方式：乘法器使用 32 轮移位加法组合逻辑生成 64 bit 乘积；除法器使用 32 轮恢复除法组合逻辑生成商和余数，未直接使用 Verilog 的 `*`、`/`、`%` 运算符实现核心乘除运算。
- 异常语义：除数为 0、`0x80000000 / -1` 等情况按照 RV32M 规则返回指定结果，便于直接运行标准 M 扩展汇编程序。
- 性能对比：原纯软件乘除法通常需要循环移位/加减并执行多条指令；该实现把乘除法封装为单条 R-type 指令，在当前单周期数据通路中由专用组合硬件一次完成，减少指令条数和寄存器/分支开销。

3. 架构优化，如pipeline【max：6】：如实现pipeline，也需要实现单周期CPU，将两种CPU整合到一个top模块中，并支持切换模式(可减小imem和dmem的大小到32KB或16KB)。需基于同一测试用例(如循环)展示CPU性能提升。能正确运行包含control hazard，data hazard的代码片段(一个或多个)
    
    - 需能够通过debug模式暂停、控制时钟周期行进，以便实时观察寄存器值和hazard解决情况
        
    - 需自行提供测试用的汇编代码并测试通过。
        
4. 软硬件协同应用【max：5】：基于CPU自创软件应用，如游戏、图像、声音处理或其他。
    
5. 教学、实验效率提升辅助工具【max：2】
    
6. 其他以上未列出的创意

2. **需确保能够使用传统拨码开关、LED等外设进行测试**
    
3. 必须使用vivado 2017.4版本进行开发
    
4. 文档和视频中需详细介绍bitstream生成流程，每个样例测试步骤，以确保inspector可在其他环境中进行复现，用于评分
    
5. 如果无法上板，需提供仿真，并展示测试方法，分数=实际仿真得分*0.3
    
6. 得分以inspector实际测试结果为准
    
7. 若inspector无法根据代码、文档和视频内容复现验证场景，需单独预约时间进行现场测试，否则0分。
